Telemetry — real AI trace spans

Both runs decide the same case (L2, a stock-pump post) and reach the same committed decision — tag Irrelevant + close. What differs is the shape of the trace: Mastra emits one agent-run span tree (LLM turn + tool calls rolled up), while the vanilla loop emits one flat LLM turn span per hand-written step.

Same agent, two builds. The framework absorbs the loop, dispatch, history, step cap, retry & telemetry wiring — you keep the judgment (schema · tools · prompt).
Mastra src/agent.ts
// the whole agent, declared — orchestration is the framework's job
const searchTool = createTool({
  id: "search",
  inputSchema: searchInputSchema,
  execute: async ({ context }) => runSearch(org, context),
})

const submitDecisionTool = createTool({
  id: "submit_decision",
  inputSchema: decisionInputSchema,
  execute: async ({ context }) => sink.submit(context), // latch + retry
})

const agent = new Agent({
  name: "Goal Agent",
  instructions: SYSTEM_PROMPT,
  model: google(MODEL),
  tools: { search: searchTool, submit_decision: submitDecisionTool },
})

// loop · dispatch · history · step cap · retry — all inside one call:
const res = await agent.generateLegacy(
  buildInputPrompt(action, org, org.goals),
  { maxSteps: 12 },
)
Vanilla src/01-vanilla.ts
// the for-loop IS the agent — you do every framework job
const TOOLS = {
  search:          tool({ parameters: searchInputSchema }), // no
  submit_decision: tool({ parameters: decisionInputSchema }), // execute
} // → the AI SDK hands the call back to US: the loop is ours

const messages = [{ role: "user", content: buildInputPrompt(...) }]

for (let step = 1; step <= MAX_STEPS; step++) {   // the loop
  const res = await generateText({
    model: google(MODEL), system: SYSTEM_PROMPT, tools: TOOLS, messages,
  })

  if (res.finishReason !== "tool-calls") break  // step cap + exit
  messages.push(...res.response.messages)          // history threading

  const toolResults = res.toolCalls.map((call) =>   // dispatch
    runTool(org, call.toolName, call.args, sink)) // + retry on error
  messages.push({ role: "tool", content: toolResults })
}
Who owns each job: tool defsthe loopdispatch historystep capretrytelemetry wiring — declared on the left, hand-written on the right.

One agent run span with three nested children — the whole multi-turn generation folded into a single LLM turn, plus a tool call span per invocation. The framework wired the tracer; the runner only narrates the tool events it surfaces.
